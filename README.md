# 泳道拆样台 + 读段号去重(fastq-demux)

测序中心同一泳道的 R1 / R2 / I1 三份**未压缩** FASTQ,按样本索引 CSV 拆出成对读段;
再对已发布运行里的单个样本做双端**读段号去重**。
FastAPI + SQLite,逐对流式处理,不整份读入内存。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

本地开发(不需要 Docker):

```bash
pip install -r requirements.txt
uvicorn app.main:app --port 8000
# 测试:pip install httpx pytest && python -m pytest tests/
```

## 使用

1. 首页填**运行号**(字母数字开头,可含 `- _ .`),上传 R1、R2、I1 三份未压缩 FASTQ
   和样本索引 CSV。
2. CSV 两列:`样本号,索引序列`;首行可为表头;索引仅允许 ACGTN(不区分大小写),
   必须**等长且唯一**;样本号唯一,且不能叫 `undetermined`(保留给未分配组)。
3. 提交后页面每 3 秒自动刷新;处理完成后按组提供 `样本_R1.fastq` / `样本_R2.fastq`
   下载、每组对数(含其中纠错对数)和处理日志 `demux.log`。
4. 在已发布运行的样本行点「去重」,即进入「读段号去重」页(见下节);
   去重记录也会汇总在首页。

## 拆分规则

- 逐对核对:R1/R2/I1 三条记录的**读段号**(头部第一个空白前)必须一致,
  每条记录的**序列与质量长度**必须一致;三份文件记录数必须相同。
- 索引**精确匹配优先**;无精确匹配时,仅当**单碱基错配候选唯一**才纠到该样本;
  候选多个或无候选一律进 `undetermined`(未分配组)。
- 各组输出严格保持输入顺序;只输出 R1/R2(I1 仅用于判定)。

## 读段号去重

入口在**已发布运行**的运行页,样本行右侧的「去重」按钮(未分配组没有去重入口,
因为它不对应一个样本)。

- 只处理该样本已发布的 `<样本>_R1.fastq` / `<样本>_R2.fastq`,**原文件不改动**。
- 按**原顺序**逐对扫描:读段号首次出现 → 保留;同号再次出现且 **R1/R2 的序列与
  质量全部相同** → 剔除;同号但内容不同 → **整次失败**,不发布任何文件或计数。
- 每对都核对 R1/R2 读段号一致、记录数一致;总对数必须等于该样本**原入库对数**,
  否则整次失败(源文件损坏或被改动)。
- 结果提供独立的 `<样本>_dedup_R1.fastq` / `<样本>_dedup_R2.fastq` 下载,以及
  「原入库对数 / 输入对数 / 保留对数 / 剔除对数」与 `dedup.log`。
  `保留 + 剔除 = 输入 = 原入库对数`。
- **读段号索引在磁盘 SQLite 里**(`staging/<token>/seen.db`,页缓存上限 16 MiB),
  不把所有读段号放进内存;输出始终流式写出。实现按**读段号整串**判定"同号"
  (头部第一个空白之前,不含 `1:`/`2:` 注释尾巴)。
- 去重结果里 R1/R2 仍是原始 4 行记录(头部、序列、分隔行、质量原样),只是去掉了
  被判为重复的对。
- 处理前后比对源文件的 stat(设备/inode/大小/mtime)并重新计算 SHA-256,
  处理期间源运行失效、源文件被替换或内容变化都会整次失败。
- 与拆样相同的原子发布:`data/published/_dedup/<运行号>/<样本>/` 写完并生成日志后
  用 `os.rename` 整体发布,再在同一事务里写计数、置为 `published`;任何异常都只
  留下 `failed` 任务与清理后的暂存区。已发布的去重结果同一样本再次发起返回 409,
  内容不会被覆盖;失败任务可再次发起。

## 可靠性设计

- **不发布半套文件**:处理中的上传件与输出都在 `data/staging/<随机目录>/`;
  全部写完并生成日志后,输出目录经 `os.rename` **原子**移到
  `data/published/<运行号>/`,同一事务写入计数并把运行置为 `published`。
  后段损坏、磁盘写失败等任何异常都会把运行标为 `failed` 并清理半成品。
- **进程中断恢复**:启动时把残留的 `processing` 运行/去重任务标为 `failed`,
  清掉其暂存目录和可能来不及落库的发布目录;无主的暂存目录一并清理;
  已发布但文件缺失的运行或去重任务标失败,保证"下载只见完整文件"。
- **重试与不可改写**:失败/中断的运行可用同一运行号重新提交直到完成;
  已发布运行同号提交返回 409,文件不会被覆盖。去重任务同理。
- **计数可信**:计数与文件在同一次逐对扫描中产生,下载页只展示已发布运行的
  完整文件与对应计数。

## 已知限制

- 仅支持未压缩的 4 行 FASTQ(不支持 .gz、不支持序列折行);上传 gzip 会以
  "不是纯文本"失败,需先解压。
- 单进程单 worker 运行(后台线程处理);不要起多个 uvicorn worker,
  否则中断恢复会误判在途运行。
- 每个样本 + 未分配组各占用 2 个输出文件句柄,样本数极多(数千)时需调高
  进程 fd 上限。
- 索引读长与样本索引长度不一致的读段进未分配组(不报错,见日志与计数)。
- 去重按**整个读段号字符串**比较(头部第一个空白前);不同 `@… 1:` / `@… 2:`
  后缀不影响判定。不支持只按坐标部分比较。
- 去重的磁盘索引大约按每个读段号几十字节占用暂存空间,处理结束即随暂存区删除;
  需要能放下与读段号数量相当的临时磁盘(实测 200 万对约 146 MB)。
- 发布前复核源文件会**再完整读一遍**源 R1/R2 算 SHA-256,即源文件读取量约为
  去重本身的两倍;这是发现"大小/mtime 被保持一致的内容变化"的代价。
- 去重输入必须是未压缩 4 行 FASTQ,与拆样一致。

## 目录结构

```
app/
  main.py      # 路由、后台处理、原子发布、启动恢复
  demux.py     # 逐对流式 FASTQ 解析与拆分核心
  dedup.py     # 逐对去重核心(磁盘 SQLite 读段号索引)
  samples.py   # 样本索引 CSV 解析校验
  db.py        # SQLite schema 与连接
  config.py    # DATA_DIR 路径
  templates/   # 页面
tests/test_app.py    # 拆样关键情形自测(pytest)
tests/test_dedup.py  # 去重关键情形自测(pytest)
data/          # 运行期生成:app.db、staging/、published/、published/_dedup/
```
